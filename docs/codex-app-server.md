# Codex App Server wake adapter

`psst-codex` is an opt-in local harness that turns durable pending Psst mail into a turn on one
durable Codex thread. It launches the installed `codex app-server` over local stdio, validates the
schema generated by that exact installed version, performs one initialization handshake, and then
resumes the configured thread. Each owned App Server process receives a process-scoped Psst MCP
configuration marked required; the adapter never mutates Codex's global MCP registrations. The
App Server thread receives exactly two closed dynamic tools. The adapter proxies those callbacks
to `message_receive` and `message_acknowledge` through App Server's `mcpServer/tool/call` API. It
rejects receive calls that try to acknowledge implicitly and rejects acknowledgement IDs that were
not retrieved during the same turn. It never sends
participant message bodies as turn input and never steers or interrupts a running turn.

This is an unreleased Slice 4 development surface. It is not enabled by MCP registration and it is
not a remote listener.

For the shared foreground start, status, stop, and restart workflow, see
[Wake harness operations](harness-operations.md).

## Configuration

Set the ordinary `PSST_RELAY` and `PSST_PROFILE` values for an already joined profile, plus:

- `PSST_CODEX_APP_SERVER=1` — exact opt-in;
- `PSST_CODEX_COMMAND` — absolute path to the installed native Codex executable;
- `PSST_CODEX_MCP_COMMAND` — absolute path to the matching `psst-mcp` executable;
- `PSST_CODEX_THREAD_ID` — the durable thread to resume.

Thread creation is intentionally separate. Omit `PSST_CODEX_THREAD_ID` and set
`PSST_CODEX_CREATE_THREAD=1` plus an absolute, nonexistent `PSST_CODEX_THREAD_RECORD` path only when
you deliberately want a new durable thread. The adapter creates that record without overwriting an
existing object, writes the new thread ID, and flushes it before beginning observation. On the next
run, use that value as `PSST_CODEX_THREAD_ID` and omit both creation variables. Supplying both
policies, neither, an invalid opt-in value, an existing record, or an invalid thread id fails closed.

Run `psst-codex` and stop it with the platform interrupt. Windows accepts Ctrl-C and targeted
Ctrl-Break so an isolated process group can drain cleanly. Its stdout is unused; fixed local
diagnostics go to stderr. The Codex child uses the default local stdio transport. WebSocket,
`turn/steer`, and `turn/interrupt` are outside this adapter's contract.

While idle, `psst-codex` owns the selected Psst profile and observes the inbox. Before it starts an
App Server turn, it shuts that observer session down and releases the profile lock. The scoped
`psst-mcp` child then owns the profile for the turn. After `turn/completed`, the adapter closes and
reaps App Server and MCP before reacquiring the observer session. This handoff prevents two local
owners from racing the same credential and lets the MCP tool process use the already-bound profile.

The protocol lifecycle follows the official [Codex App Server
documentation](https://learn.chatgpt.com/docs/app-server): initialize once with the experimental API
capability, emit `initialized`, resume or explicitly start a thread with the two dynamic tools, call
`turn/start`, proxy only their `item/tool/call` callbacks, then await `turn/completed`.
